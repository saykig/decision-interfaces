# Active mathematical goals — September 21, 2026

This is an additive operating plan after R16 and R17, not a replacement for the
north star or inherited history. Decision Interfaces is an independent mathematical
research programme. Neither CEES page limits nor selecting an empirical case
constrains its theorem agenda. Empirical transfer belongs outside this repository;
transfer between mathematical model classes is a legitimate foundation test.

## Stable question

What is the least information a decision component must expose to preserve a
declared family of strategic conclusions, accurately and under specified composition,
reuse and revision operations?

## Current standing

R15/R16 give written exact-interface, operational-error, compression-rate and
finite/unlimited-reuse results for the declared hard-evidence benchmark. R14 checks
beliefs, receiver choices and mixed continuation gains in Lean, not the full target-
existence theorem. R17 now provides a tested arbitrary-order reference for one
planar uncertain block with known-probability senders. None of this is a claim of
novel geometric entropy or a universal enforcement architecture.

## Gate A — finish usable query coverage

Integrate the R16 binary decoder and the existing R10/R12 exact machinery. Build an
all-permutation reference accepting arbitrary rational V-polytope contexts before
optimizing it. Preserve positive ratios, favorable ties, one common order across
models, exact masks for finite shared labels and the difference between modelwise
and common-order success. Add repeated independent compressed blocks explicitly.

Compare the optimized algorithm with that reference on small cases. Reuse prior
polynomial segment/fixed-dimensional results rather than presenting enumeration
as a new efficient theorem. Broader uncertainty dimension can demand new algorithms.
Return one safe order for ZERO, complete all-order evidence for FULL, REFINE only
for unresolved approximation, and UNKNOWN for incomplete computation. Cross-check
full-order conclusions from the primitive game on small cases, not only formulas.

Acceptance: source-bound end-to-end codec/query tests; exact ties, interior witnesses,
shared constraints, repeated occurrences and all orders covered in the declared
implemented class; explicit limits for runtime and trusted backends. R17 is a
first completed subset of this gate, not the whole gate.

## Gate B — formalize the two high-value bridges

In parallel with Gate A, extend R14 to the assessment predicate, both backward
arguments, arbitrary mixed continuations, and attained 0-or-B minimum. Do not
assume the cascade condition in a definition and then claim it was derived.

Next formalize rational sandwich -> support bound -> contextual margin interval,
then directed product addition and bounded-reuse accounting. Attainment/minimality,
unlimited-repeat collision and finite-label/tree induction follow as separate
statements. Record conditional dependencies rather than claiming end-to-end Lean
coverage prematurely. No new formalization was executed when writing this plan.

Why: the first bridge checks that the formula describes the actors; the second
checks that a compressed description cannot change the justified decision.

## Gate C — test a genuinely nonbinary enforcement frontier

Use one explicit finite strategic model in which action incentives generate a
nonconstant minimum sanction over a real interval. State the target, observability,
credible intervention, costs, timing, player/analyst knowledge and equilibrium
selection. Keep existence versus universal stability separate.

Ask whether the present downward/log-support interface preserves the entire
minimum-enforcement function. First seek two systems with the same present
interface but different continuous enforcement answers. Such a counterexample
identifies what the next interface must expose. If the interface survives, prove
sufficiency and necessity for a declared class and derive an operational error
bound. Do not simply define a supremum of violations and call it a new theory.
Do not add rewards, vector sanctions, dynamics and bargaining simultaneously.
Move to those when a result explains what they add or require.

## Literature and serendipity

Audit novelty theorem by theorem across decision-preserving coding, experiments,
abstract interpretation, quantitative assume-guarantee reasoning and incentives.
Name the closest statement, match its hypotheses and prove or refute implication.
Related vocabulary is neither proof of novelty nor proof the problem is solved.
Flag CANDIDATE ORIGINAL THEOREM when a precise new result survives this test; record
remaining priority uncertainty. Lean checks correctness, not historical novelty.

Follow unexpected structures with a concrete proof/counterexample target. Retain
one main question. A different question is earned by subsumption, a false premise,
a recurring stronger mechanism or a demonstrably better theorem, not by novelty
of the topic alone. Research need not wait for every formalization task to finish.

## Milestone, not intellectual ceiling

The first mathematical manuscript closes when its exact query contract, strategic
bridge, compositional error theorem, rate/reuse boundary, executable end-to-end
reference and source/novelty comparison form a checkable package. Record any remaining
formal and human-review gaps explicitly. Empirical transfer, Ukraine analysis,
a welfare theory, dynamics and bargaining are not prerequisites for that manuscript.

The programme continues by deriving interfaces between genuinely different model
classes. Gates A/B are definite next tasks. Gate C's answer determines whether the
next step is a larger interface, a sharper impossibility, or a broader sufficiency
theorem; do not precommit to a distant sequence of extensions.
